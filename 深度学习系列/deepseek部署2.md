# 为什么是DeepSeek？

- 性能比肩 OpenAI o1 模型
- 支持 “思维链”。DeepSeek-R1 系列在回答问题前进行思考，即输出答案前展示“思维链”（Chain-of-Thought），增强透明度和可信度。
- 更低的训练成本：
  - DeepSeek-V3 671B 的模型，训练总成本约为557.6万美元。采用2048个H800集群，总计GPU小时越278.8万，租赁成本按每小时 2 美元计算。
  - Meta 的 Llama3.1-405B 训练成本 6000w 美元
  - OpenAI GPT-4 训练成本数亿美元
- 更低的推理成本/更快的推理速度：
  - API 定价仅为 OpenAI 的 1/30 ~ 1/20，且响应速度更快（平均0.8s）。
  - Qwen 推理速度演示
  - DeepSeek-R1 推理速度演示
  - 结果 Qwen 比 DeepSeek-R1 快

> 总结
>
> - 性能比肩 OpenAI o1
> - 能够透明的看到思考过程
> - 训练便宜
> - 部署便宜/推理速度快

## 修改模型参数

修改 ollama 的模型的参数，如温度、最大的上下文长度。

```shell
# Modelfile generated by "ollama show"
# To build a new Modelfile based on this, replace FROM with:
# FROM deepseek-r1:1.5b

FROM /home/hp/Code/DeepSeek-R1-Distill-Qwen-1.5B-Q2_K.gguf
TEMPLATE """{{- if .System }}{{ .System }}{{ end }}
{{- range $i, $_ := .Messages }}
{{- $last := eq (len (slice $.Messages $i)) 1}}
{{- if eq .Role "user" }}<｜User｜>{{ .Content }}
{{- else if eq .Role "assistant" }}<｜Assistant｜>{{ .Content }}{{- if not $last }}<｜end▁of▁sentence｜>{{- end }}
{{- end }}
{{- if and $last (ne .Role "assistant") }}<｜Assistant｜>{{- end }}
{{- end }}"""
PARAMETER stop <｜begin▁of▁sentence｜>
PARAMETER stop <｜end▁of▁sentence｜>
PARAMETER stop <｜User｜>
PARAMETER stop <｜Assistant｜>
PARAMETER num_ctx 8192 # 设置模型输入的最大 token 数，费显存。
PARAMETER temperature 0.9 # 设置模型温度
```

temperature 越大（温度越高），数据的分布越均匀，随机性越强；温度越低，数据分布越陡峭，回答的内容越固定。

## 问题

```shell
$ sudo apt install docker
$ sudo apt install docker-compose
$ cd diffy/docker
$ docker-compose up -d # 出错了！！！
```

我相信大家在使用 docker 部署都会遇到很多问题。首当其冲的就是 docker-compose up -d 怎么出错啦！！！

```shell
docker-compose up -d
ERROR: Invalid interpolation format for "CONSOLE_API_URL" option in service "x-shared-env": "${CONSOLE_API_URL:-}"
```

这是因为 docker-compse 版本不够高。下载一个高版本就可以了。

```shell
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose 
```

这样命令是不是看不懂？其实就是字符串拼接，uname -s 获取操作系统信息（Linux），uname -m 获取系统架构（x86_64）拼接起来就是

```shell
https://github.com/docker/compose/releases/latest/download/docker-compose-Linux-x86_64
```

`-o` 是把文件下载到 `/usr/local/bin/docker-compose`

接下来执行命令，使其变成一个可执行文件

```shell
$ sudo chmod +x /usr/local/bin/docker-compose
```

然后就可以正常使用

```shell
$ docker-compose up -d
$ # 转圈圈，没法下载镜像
```

这时候需要给 docker 配置国内镜像。这些镜像可能会随着时间的变化失效！

```shell
# 编辑文件 /etc/docker/daemon.json 没有的话就新建一个
# 将下面的内容复制过去
{
  "registry-mirrors": [
    "https://docker.1panel.live",
    "https://hub.rat.dev",
    "https://register.liberx.info",
    "https://ylwibnfw.mirror.aliyuncs.com"
  ]
}
```

保存文件后，重新启动 Docker 服务

```shell
$ sudo systemctl daemon-reload
$ sudo systemctl restart docker

# 测试下镜像的配置是否生效
$ sudo docker info | grep "Registry Mirrors"
```

# 安全&性能问题

> Ollama 部署的安全问题

- 个人部署：由于只是个人使用，其他人页无法通过 IP 访问你的网络，不存在什么安全问题。
- 内网部署：将DeepSeek 部署到单位内部网络，仅单位内部网络的用户可以访问，不存在什么安全问题。
- 公网部署：Ollama 部署的模型，默认情况下，任何人都可以访问！会出现被偷算力！可通过设置防火墙白名单来避免被外人恶意访问，盗取算力。

> dify + ollama 的调用原理

dify 是一个后端 web 服务 + 前端 UI

ollama 提供的是后端服务

dify + ollama，本质上就是 dify 调用 ollama 的 API。如果两个都在同一台电脑，那么可以通过防火墙限制，只允许本机访问 ollama（本机的 IP）。

> Ollama 的性能问题

- Ollama 并发性能一般，不支持被多人/大规模的访问使用。并且，设置模型并行是会出现 bug。

> 大规模部署的最佳选择

既然选择了大规模部署，就表明不缺显存~

- vllm：大规模部署 LLM 的主流选择。大公司首选。
- lmdeploy：极致的显存管理，极致的推理速度。

# 微调 DeepSeek

## 根据参数量进行划分

- 全量微调：对模型的所有参数进行更新，使其适应特定任务。能够充分利用模型的全部能力，但是需要大量的计算资源和时间。极有可能导致模型的通用能力极大地退化
- 部分微调：仅更新模型的部分参数，冻结模型的大部分层，只微调最后几层或特定模块。
- 参数高效微调（PEFT）：在预训练模型中添加少量可训练的参数或模块，仅训练这些新增的参数，减少资源消耗，提高效率。

## 根据任务进行划分

按训练目标划分的微调方式

| **类型**                 | **核心思想**                     | **典型方法**                        | **适用场景**                   |
| ------------------------ | -------------------------------- | ----------------------------------- | ------------------------------ |
| **监督微调（SFT）**‌      | 基于标注数据直接优化任务性能     | 传统分类/生成任务微调               | 标注数据充足（如翻译、摘要）   |
| **强化学习微调（RLFT）**‌ | 通过奖励信号优化输出对齐人类偏好 | RLHF、DPO、PPO                      | 需对齐人类价值观（如对话生成） |
| **自监督微调**           | 利用无标注数据生成伪标签优化模型 | MLM（掩码预测）、对比学习（SimCSE） | 标注数据稀缺但无标注数据丰富   |

- 监督微调：

  - 指令微调

  - 多轮对话微调

## 微调工具

- LLaMA-Factory，支持海量模型和各种主流微调方法，包括 LoRA341。它提供了运行脚本微调和基于 Web 端微调的能力，自带基础训练数据集，并支持增量预训练和全量微调。（小白用这个）
- Hugging Face 的 PEFT 和 Transformers，支持 LoRA、AdaLoRA 等。
- XTuner，支持在几乎所有 GPU 上对 LLM 和 VLM 进行预训练和微调，包括在 8GB GPU 上微调 7B 模型。它支持多种模型（如 InternLM、Llama2、ChatGLM、Qwen、Baichuan 等）和训练算法（如 QLoRA、LoRA、全参数微调），并提供从微调到部署、评测的完整工具链。（大佬用这个）
- Unsloth，它可以将微调速度提升 2 倍，内存占用减少 80%，支持多种主流 LLM，如 Llama 3.1、Mistral、Phi - 3.5 和 Gemma 等64。Unsloth 提供完整的 Colab 教程，支持 Hugging Face 生态，适合 AI 开发者、学术研究者、企业技术团队和学生爱好者使用。（大佬用这个）
